## New local workflow

- `capability-graph` correlates exact Skill bytes with bounded local configuration and reports `declared-enabled`, `declared-disabled`, `not-declared`, or `unknown`.
- `capability-graph-compare` explains changes in saved baseline and current graphs, separating Skill bytes, declarations, and captured context. Complete `changed` and `unchanged` comparisons exit 0; incomplete or version-limited evidence exits 2.
- `review-record` retains one complete supported graph in a caller-declared receipt. `review-check` compares that receipt with a supplied fresh graph: `matches-evidence` exits 0, `changed-since-review` exits 1, and `cannot-check` exits 2.

Captures do not execute the Skill or upload source. Receipts are **unsigned, unauthenticated, and advisory-only**: they do not prove human review, capture authenticity, installation continuity, restoration history, or safety. Always recapture before checking. Commands refuse to overwrite existing evidence and never update configuration or promote changed evidence automatically.

Declared configuration does not establish runtime discovery, reachability, initialization, permission in effect, or authority to execute. Hosted monitoring, organization policy, a dashboard, and runtime protection are outside this candidate. See the [full evidence contracts and limits](../skill-review.md).
