# v0.7 Agent Skill snapshot foundation

Status: unreleased developer foundation on `codex/v0.7-artifact-foundation`. This does not change the reviewed v0.6.3 release, MCP report schema, scanner rules, or GitHub Action.

Do not publish a package from this branch under the retained `0.6.3` package version. The MCP analyzer version is now frozen separately so an eventual v0.7 release cut can identify the new package without changing legacy MCP scan IDs.

## Purpose

The first v0.7 slice establishes exact local artifact identity before Uleravo attempts Plugin support, harness permissions, normalized capabilities, or semantic deltas. It answers a deliberately smaller question:

> Which regular files and declared Skill metadata were safely observed for this exact local Agent Skill?

It does not decide whether a Skill is safe or permitted in a particular harness.

## Command

```text
uleravo snapshot ./path/to/skill --kind skill --format json --output skill.snapshot.json
```

The target can be a Skill directory or its exact `SKILL.md` file. The command exits `0` only when the artifact closure and required manifest metadata are complete. It exits `2` for malformed metadata, unresolved links, unsafe filesystem entries, read races, or exhausted limits. Snapshotting does not use exit code `1` because this slice makes no finding-threshold decision.

`--output` must name a new file outside the Skill root. Its parent must already exist and must not traverse a symbolic link or junction. Uleravo refuses to overwrite an existing output path.

Optional `--repository-url` and `--commit-sha` values must be supplied together. They are recorded as `user-supplied` and `endpoint-unverified`; the snapshot never invokes Git or contacts the URL.

## Current Skill contract

This adapter recognizes a directory with a required `SKILL.md`. That file must contain YAML front matter with non-empty string `name` and `description` fields and non-empty instructions after the front matter. Other regular files—including binary scripts, references, assets, and `agents/openai.yaml`—are hashed as opaque artifact content. They are never executed, imported, or interpreted in this slice.

The YAML reader uses the failsafe schema and rejects duplicate keys, aliases, anchors, custom tags, non-string required fields, invalid UTF-8, and front matter above 256,000 bytes.

## Closure and digest

The closure includes every regular file below the Skill root except files inside real, non-link VCS administrative directories named `.git`, `.hg`, and `.svn`. A regular file with one of those names remains in the closure, and a link with one of those names makes capture incomplete. It does not honor `.gitignore`. Directory entries are streamed under a global encountered-entry budget, then the bounded set is sorted by Unicode code unit after conversion to portable, relative POSIX paths.

The domain-separated `contentSha256` is computed over:

1. artifact kind;
2. for every file in sorted order, its framed UTF-8 relative path;
3. its unsigned byte length; and
4. its raw-file SHA-256 bytes.

Absolute paths, modification times, wall-clock timestamps, duration, diagnostics, analyzer version, and evidence wording do not enter the content identity. Binary auxiliary files are hashed without decoding. `contentSha256` is withheld whenever the full closure cannot be safely resolved; `observedSha256` still identifies only the subset that was safely read.

Local directory capture is labeled `best-effort` because a filesystem traversal is not an atomic snapshot and Node.js does not expose portable descriptor-relative recursive traversal. Each directory and file is freshly inspected, canonically contained, and checked before and after bounded access. A detected replacement, mutation, link, or containment change fails closed. Hosted ingestion should inspect a scanner-owned immutable materialization rather than a customer-mutable tree.

Default limits are 1,000 files, 10,000,000 bytes per file, and 50,000,000 total bytes. Library callers may lower them or raise them only within hard caps.

Canonical JSON reports are limited to 10,000,000 bytes. If repeated long evidence paths would make the report larger, snapshot creation fails closed and produces no partial oversized report; callers can lower the file limits or use shorter materialized paths.

## Evidence labels

Identity, closure, manifest, repository, and coverage claims use explicit evidence sources:

- `observed`: directly read local bytes or filesystem facts, never runtime behavior;
- `declared`: values stated in supported manifest fields;
- `inferred`: conclusions Uleravo derives without runtime observation; and
- `user-supplied`: optional identity context provided by the caller.

Claim states are `resolved`, `mutable`, `unresolved`, `endpoint-unverified`, `unsupported`, or `unavailable`. The initial report intentionally marks capability normalization as `unsupported`, harness permissions as `unavailable`, and Skill version as `unavailable`. A content digest identifies exact bytes but does not make a mutable local folder immutable.

## Security boundary

Snapshotting performs local bounded reads only. It never:

- executes Skill scripts or target code;
- imports target modules;
- runs package managers, Git, hooks, or MCP servers;
- intentionally follows symbolic links or junctions;
- accepts an observed path that resolves outside the canonical Skill root; or
- initiates network requests.

Declared text and display labels pass through Uleravo's output redaction defense. A path that resembles sensitive data is withheld, makes closure incomplete, and is never added to the report. Full source contents and binary bytes do not appear in the report.

Consumers can validate stored reports with the library's `readArtifactSnapshot(path)` or `parseArtifactSnapshot(json)` APIs. Both enforce the bounded canonical contract and recompute totals, identities, completeness, and cross-field evidence relationships; the JSON Schema provides the complementary structural contract.

## Deferred work

This foundation intentionally defers recursive discovery of multiple Skills, Plugin manifests, archive ingestion, a selected harness adapter, capability normalization, semantic delta, signed advisory decisions, remediation, hosted upload, accounts, billing, and dashboards. Those features should extend the artifact adapter/report boundary rather than widen the stable MCP `ScanReport` contract.
