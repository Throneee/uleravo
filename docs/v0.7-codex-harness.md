# v0.7 Codex local-configuration harness

Status: v0.7.0 local harness contract, unchanged in candidate package 0.8.0-rc.1. The harness analyzer remains 0.7.0; the independent MCP analyzer remains version 0.6.3. The immutable released package remains 0.7.0.

## Purpose

The first Uleravo harness adapter answers a bounded question:

> Which security-relevant capabilities and permissions are declared by the supplied local Codex configuration layers, and how did those declarations change between two snapshots?

It is not a runtime monitor, policy-enforcement boundary, plugin verifier, or assertion that every effective Codex setting was reconstructed.

## Commands

```text
uleravo harness ./project \
  --user-config ~/.codex/config.toml \
  --requirements /etc/codex/requirements.toml \
  --codex-version 0.138.0 \
  --format json \
  --output codex.harness.json

uleravo harness-delta baseline.harness.json current.harness.json --format text
```

When a path option is omitted, Uleravo detects the normal user `config.toml`, project `.codex/config.toml`, and platform system `requirements.toml` locations. `--skip-user-config`, `--skip-project-config`, and `--skip-requirements` mark a layer disabled rather than conflating it with an absent detected file. An explicitly supplied missing file is an error; an absent detected optional layer is recorded as unavailable.

The optional `--codex-version` is caller-observed evidence. Uleravo binds it into the input digest and snapshot ID but never invokes a Codex binary to discover a version.

## Normalized surface

The report records:

- legacy sandbox mode, named permission profiles, workspace writable roots, filesystem rules, Windows sandbox declarations, and legacy or permission-profile command-network policy;
- approval posture, web-search mode, selected high-impact feature flags, and project trust;
- configured Skill paths and explicit enablement;
- configured Plugin and App identifiers, tool enablement, open-world/destructive toggles, and approval modes;
- MCP transport identity, explicit enablement, tool allow/deny lists, per-tool approvals, OAuth scopes, and environment/header names; and
- lifecycle hook events, handler type, executable or MCP-tool identity, matcher digest, and async declaration.

Environment and HTTP-header values are never copied into the report. MCP URL display identity omits credentials, fragments, and all query values while retaining the scheme, host, path, and sorted query-parameter names; a separate SHA-256 identity over the unreported URL detects value-only changes. MCP arguments, full hook handlers and matchers, proxy endpoints, and managed hook paths use domain-bounded SHA-256 identity where their contents are not safe report material. Every inventory item carries its source layer and applicability.

Project config is included in the local composite only when the user config contains one unambiguous matching `projects.<path>.trust_level = "trusted"` declaration. An untrusted project layer remains visible but is marked ignored. If trust is unavailable, the layer is marked unknown and its declarations do not become semantic facts.

System requirements are recorded as constraints, not as proof of complete enforcement. The adapter recognizes approval/sandbox/web-search allowlists, permission-profile constraints, deny-read rules, managed networking, feature pins, hooks, Apps, Plugins, and MCP identity allowlists. Cloud-delivered requirements, MDM preferences, legacy managed config, and field-specific multi-source merge state remain unavailable unless a future adapter accepts those layers explicitly.

## Semantic permission delta

Facts have stable keys, source evidence, a value, and an effect class: exposure, guard, posture, or identity. Known ordered postures carry a rank. The delta classifies:

- a higher sandbox, web-search, or autonomous-approval rank as expanded access;
- enabled features, added writable roots, Skills, Apps, MCP servers/tools/scopes, environment names, and allowed network destinations as expansions;
- added deny rules and managed guards as reductions; and
- executable, URL, matcher, or otherwise unordered posture changes as changed rather than guessing their security direction.

Explicit false exposure declarations are reductions, and allow-to-deny transitions are reductions; the inverse transitions are expansions. Removing a fact reverses its addition direction. The comparator refuses incomplete captures and snapshots whose project-config applicability is unknown, rather than presenting missing or ambiguous evidence as a real permission change. It does not assign vulnerability severity or claim that a configured capability initialized successfully.

## Safety and completeness

Each input is a bounded, stable, regular UTF-8 file parsed as TOML data. The adapter rejects linked files, read races, malformed TOML, and over-limit inputs. It never executes or imports target code, invokes hooks or commands, starts MCP servers, opens configured URLs, performs OAuth, launches Codex, or initiates network requests.

The output is deterministic for the same bytes, selected layers, trust declaration, and supplied Codex version. It intentionally has no wall-clock timestamp or duration. `capture.complete` means the selected local files were safely read and normalized; the separate `effective-runtime-state` coverage entry always remains unavailable because profile files, dedicated CLI/session overrides, product defaults, cloud/MDM requirements, installed artifact discovery, and initialization results were not observed.
